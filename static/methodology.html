Methodology

Evidence before confidence.

AI Code Audit is an intent-aware static review assistant. It examines supported source code without executing it and reports evidence that deserves review.

Important: A clean result means no supported risk signal was found. It does not prove that code is safe, correct, or ready for production.

What the scanner evaluates

  • Credential access and possible secret exposure
  • Unexpected network connections and credential transmission
  • Risky execution, shell commands, unsafe deserialization, and download-to-execute behavior
  • File access, hidden telemetry, obfuscation, and persistence signals
  • Behavior that may conflict with the user’s stated intent
  • Known dependency vulnerabilities and selected package-supply-chain signals

How the audit score works

The 0–100 audit score is a deterministic, risk-weighted index for comparing revisions. It is not a probability, certification, or measurement of total security. Findings contribute risk points; the score is 100 minus those points, bounded between 0 and 100.

Score bandPrimary verdict
0–65Do not run this yet
66–90Review before running
91–100No major supported risks found; continue testing

Accuracy evidence

Regression testing includes internally labeled multi-language scenarios and pinned OWASP BenchmarkPython cases. Python has the strongest external benchmark evidence. JavaScript and TypeScript results are internally curated regression evidence, not an independent production benchmark. Exact current measurements are published through the accuracy status endpoint and in the repository.

Known boundaries

  • Submitted code is not executed.
  • Runtime-only behavior may be missed.
  • Cross-file and framework-specific flows are limited.
  • Complex dependency resolution, private registries, and generated manifests may be skipped.
  • The service is a review aid, not a penetration test, compliance certification, or replacement for professional security review.
