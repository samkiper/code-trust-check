Support

Start with the symptom.

For public product questions, reproducible bugs, false positives, or feature requests, use the project’s GitHub issue tracker.

Do not post secrets or private account information. Public issues can be viewed by anyone. Never include API keys, passwords, payment details, private source code, or private repository names.

Choose the right route

  • Report a reproducible bug
  • Report a false positive or missed risk using a minimal non-sensitive example
  • Request a feature
  • Privately report a service vulnerability

Before reporting a scan problem

  1. Record the scanner version and whether the scan was pasted code, a public repository, or a GitHub pull request.
  2. Check the coverage panel for skipped files, language depth, and engine status.
  3. Remove all credentials and private information from any example.
  4. Reduce the example to the smallest code sample that still reproduces the behavior.

Billing and account questions

Use the in-product billing portal to manage or cancel Pro. Do not place account-specific billing or identity information in a public GitHub issue. A private billing and privacy contact address still needs to be published before broader commercial launch.
